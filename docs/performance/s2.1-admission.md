# S2.1: admission for the whole request

Measured 2026-11-15 after S2.1, same machine and payloads as the [baseline](baseline.md).

## What changed
- Admission moved from the core handler (it covered only validation) to request middleware
  that holds the slot for the whole request: body read, decompression, decoding, validation.
- Default limit: 2 × CPU count, min 8 (22 here, instead of 64).
- Refused requests have their unread body drained, so HTTP/2 streams end normally. Without it,
  refusals at load were seen as an HTTP/2 "rapid reset" pattern (CVE-2023-44487) and Kestrel
  closed the connection (ENHANCE_YOUR_CALM, hung calls). See `RefusalFlowControlTests`.
- The load generator now honors the retry delay (gRPC RetryInfo, HTTP Retry-After) like real
  exporters, has a per-export timeout, and reads the server's GC counters over EventPipe.
  "NO backoff" marks the worst case: a client retrying at once.

## Compared with the baseline (gRPC, batch 512)

| concurrency | OK exports/s: baseline → S2.1 | p99 ms | peak RSS MB |
|---|---|---|---|
| 32  | 4,616 → 4,848 | 14.4 → 9.2 | 1,031 → 768 |
| 64  | 4,546 → 4,833 | 30.7 → 9.9 | 1,585 → 802 |
| 128 | 4,538 → 4,851 | 50.1 → 9.8 | 1,721 → 842 |

- **Memory is now bounded**: flat from c32 to c128, where it used to keep growing.
- **Throughput is unchanged or slightly better, and tail latency is 3-5× lower**: excess
  exports wait on the CLIENT (backoff), not in the server's queues.
- **A client ignoring backoff** (retry storm) still gets served, but costs ~75% of the
  throughput: refusals aren't free, because receiving and draining a body is most of an
  export's cost. Real OTel exporters honor RetryInfo / Retry-After.

## What the GC counters show (input for S2.2)
- **8192-record batches: the GC heap itself peaks at ~2.1 GB with 8 exports in flight**, so
  it is NOT memory the GC merely keeps in reserve. Each export allocates ~25.7 MB, mostly
  large buffers (> 85 KB) that go to the large object heap (LOH), which is only collected by
  gen-2 GCs, and there were none in that run: the LOH garbage piles up.
- **HTTP/protobuf: 33% of time in GC and ~1,050 gen-2 GCs in 15 s.** The request body is
  buffered in a growing MemoryStream (LOH-sized copies as it grows).
- Allocated per 512-record export: ~1.5 MB over gRPC, ~1.9 MB over HTTP, ~8 MB over JSON, for a
  253 KB message.

Both point at the same S2.2 work: pooled buffers for request bodies, off the LOH.
