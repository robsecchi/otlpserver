# S2.2: pooled buffers for OTLP/HTTP request bodies

Measured 2026-11-15 after S2.2, same machine and payloads as the [baseline](baseline.md) and
[S2.1](s2.1-admission.md).

## What changed
- OTLP/HTTP bodies are built from pooled 128 KiB blocks (`Microsoft.IO.RecyclableMemoryStream`)
  instead of a new, growing `MemoryStream` per request, and decoded straight from them (no
  copy). Blocks go back to the pool right after decoding, before validation. At most 128 MiB of
  free blocks are kept.
- gRPC is unchanged: grpc-dotnet already hands the message over as pooled Kestrel memory.
- Load test: GC-mode experiment rows added.

## HTTP: baseline → S2.1 → S2.2 (batch 512, concurrency 32)

| | OK exports/s | p99 ms | % time in GC | gen-2 GCs (15 s) | peak RSS MB |
|---|---|---|---|---|---|
| protobuf | 4,134 → 5,719 → **8,275** | 16.8 → 13.3 → **9.6** | ? → 32.9 → **10.2** | ? → 1,049 → **0** | 601 → 640 → 607 |
| protobuf + gzip | 5,667 → 5,708 → **9,212** | 30.4 → 31.8 → **8.4** | ? → 10.3 → 10.8 | ? → 219 → **0** | 940 → 1,089 → **536** |
| JSON | 951 → 854 → 963 | 91.5 → 116.9 → 84.0 | ? → 11.6 → 11.7 | ? → 129 → 129 | 1,277 → 1,394 → 1,226 |

(The baseline had no GC counters.)

- **HTTP/protobuf: +45% over S2.1 (+100% over the baseline), gen-2 GCs gone**, GC time down from
  33% to 10%. With gzip: +61%, and half the memory.
- **HTTP is now faster than gRPC** on this machine (8.3k vs 4.9k exports/s). The remaining gRPC
  cost is its own per-call work plus the shared decode + validation allocations (S2.3).
- **JSON barely moves** (+13%): its cost is the JSON DOM and the double parse, not the buffer.
  The 129 gen-2 GCs come from inside the JSON parser.
- **gRPC + gzip still causes ~270 gen-2 GCs**: grpc-dotnet decompresses each message into a new
  array (~253 KB here, so on the large object heap). A candidate for later.
- **8192-record gRPC batches are unchanged** (~2.2 GB, ~23 MB allocated per export): that's the
  decoded objects plus validation, which S2.3 addresses.

## GC mode experiment
| b8192 c8 | exports/s | % time in GC | peak RSS MB |
|---|---|---|---|
| Server GC (default, DATAS on) | 280 | 9.8 | 2,202 |
| Server GC, DATAS off | 279 | 10.0 | 2,351 |
| Workstation GC | **53** | **57.7** | **4,092** |

Workstation GC is 3-5× slower and uses MORE memory, at both batch sizes and on both transports
(58-67% of the time in GC). DATAS makes no difference here. **Decision: keep the default
Server GC.** (Under Workstation GC the "GC heap" counter reported values above RSS, so those
heap figures are not reliable; throughput, GC time and RSS are.)
